# ADR 0011: Counterfactual intervention analysis

Status: accepted, 2026-09-25

A failed run shows what happened, not which earlier event the failure depended on. Forks already let a user change one execution condition at a checkpoint by hand. Twinwright now automates that as intervention analysis: fork a completed, failed root run at candidate events, change exactly one controlled variable per fork, execute the child, judge it with the same success definition, and rank candidates by how many forks changed the outcome.

Replaying the parent's recorded assistant turns after an intervention was rejected. Those turns answered the original observations, so replaying them measures nothing about the agent. Each fork is executed downstream with the run's provider, or with the replacement one, and judged independently. Direct world-state edits at a checkpoint were also rejected for now: they would need a new audited mutation path, and a changed retrieved record can be expressed as a changed observation of the read that returned it.

An intervention file is strict version 1 YAML. The kinds are a replacement chaos policy, a replacement principal policy, and a set or cleared legacy fault, each applied before a targeted call is dispatched; a replacement provider or model for the decision that follows a targeted call's response; and a substituted tool response at that response. Inline policies are validated by the existing parsers. A legacy fault is rejected on a run with a chaos policy, and a chaos policy on a run with a legacy fault, because it would clear the fault too. An intervention that names the run's own fault, or a provider and model that behave identically to the run's, is rejected as no change. A tool response body keeps its number literals exactly. Only root runs are accepted, with an explicit error for a fork. Every target, fork option, and provider is validated before the first fork is created, so a configuration error writes nothing, and the database is opened for writing only after that validation. The first model decision has no checkpoint before it and is never a candidate.

Substituting a tool response is new and touches replay. The override must name the call whose `tool.response` is the fork checkpoint. In the child only, it rewrites that call's transcript message and saved result, so a reused call ID returns what the child saw, and it leaves world state unchanged on purpose. The fork transaction records the override in `fork_observations` and appends an `observation.overridden` event after `execution.forked`, with the call, operation, original status, new status, and body. Replay reads the row, applies the same change and event, and compares the event as semantic, so changing or deleting either the row or the event diverges. Databases without the table read as having no overrides. Assertions on such a child still see the parent's original response in the inherited prefix, followed by the override event, which assertions may match.

Success is an assertion file when given, otherwise the scenario evaluation. A fork that fails to execute is counted as errored, and one that does not complete within the step limit is counted as incomplete; neither counts as a change. The report states its method, the judged failure, the intervention digest, and per candidate the event, checkpoint, counts, a one-line summary, and each fork's run ID, status, and failed checks. Forks are normal child runs with lineage that replay, compare, inspect, and evaluate accept.

The counts are counterfactual sensitivity over the forks that ran. They are not probabilities and not formal causal inference: interventions are chosen by the user, candidates are not independent, and one change can mask another. Scripted fixtures make every trial identical; repeated trials matter only for a nondeterministic provider, and no live model run has been verified. Forks of forks remain unsupported, so only root runs can be analyzed. Memory items and execution strategy are not intervention kinds yet. An analysis that aborts partway leaves the forks it already created as isolated children.
